# Companion ownership

## Product stage: POC

Recruiters.rip is a proof of concept. Prioritize a working end-to-end product and fast iteration over preserving previous work. Breaking API/schema changes, replacing failed implementations, and discarding POC data are acceptable. Do not spend time on legacy-version compatibility, migration machinery, archives, or preserving obsolete experiments unless the user explicitly requests it. Keep resets scoped to this POC; credentials, authentication/security boundaries, unrelated products, and truthful result reporting remain protected.

## Current ownership

- Own the Electron companion, Chrome extension source and packaging, local career/job/form data (plain private JSON, no keychain or at-rest encryption), local MCP transport/tools, conversation skill, document codec/baseline/layout/PDF source, installer packaging and public-release updates in this repository.
- Website account authentication, checkout, download hosting, pairing UI and signed-device proxy belong to `recruiters-rip-frontend`. Middleware authorizes devices and current paid job-feed access. Do not import sibling repositories or add database/server inference dependencies.
- Preserve app ID `rip.recruiters.companion`, product name `Recruiters.rip Companion`, storage name `Recruiters Companion`, protocol `recruiters-companion`, and production `device` directory. Never inspect, mutate, reset or migrate a user's actual vault as a test.
- Production defaults to `https://recruiters.rip`. Local-product mode is explicit and isolated. Account connection opens `/settings/provider` with `deviceId`, `publicKey`, and `deviceLabel`; 
- Keep career data, captured jobs, form drafts and applications in the local vault. The recruiters.rip/JobStash servers never receive facts, applications or provider keys. The single exception is the consented JobStash profile share: with standing consent (withdrawable and re-grantable in Settings), the companion sends one CV plus the employers the agent matched to JobStash entities over the signed device relay. New feed access requires real current membership; user-captured jobs and saved local data remain available without it. The extension receives prepared field values automatically and holds no credentials; focusing an empty, supported field prepares its answer for native paste. It does not inject field writes, click submit/next controls or upload files. Agent-driven applications use the host's computer-use mouse, keyboard and native file picker in the user's browser, respect host/tool permissions, recheck the saved application context and blocks before proceeding, and report only observed results. Never bypass a block or site security challenge, overwrite populated fields without the user's instruction, or invent protected/consent answers. Optional Decisions requests require no extra local confirmation. API keys are entered in companion settings, stored outside career data, never exposed to the extension, MCP, chat, exports or logs. Never manufacture entitlements or authentication.
- Final recommendations, gap interviews and new application text belong to official user-subscription apps. The optional OpenAI Decisions API selects known values for browser-form fields only; it does not assess or prioritize jobs, invent facts or generate prose. Keep requests bounded, cancellable and bound to current career/credential context. Do not add other inference services, credential scraping, live inference in CI or fallback web-job search. Facts remain useful interview answers, not provenance ceremony; unsupported claims are fixed by the agent rather than asking candidates to certify output.
- `package.json` is the single version source. Generated code/plugins, dependencies, installers, certificates, secrets, vaults and user exports are not source-control inputs. The document source closure and required assets must remain buildable from this clone alone; retain the font license in packaged output.
- Read and follow [design.md](design.md) before every UI change. It records the approved design artifact, current tokens, component rules, screen designs and verification requirements. Use `ui/design-tokens.css`, the bundled Instrument Serif/Geist/Geist Mono fonts and supplied brand assets. The companion is a dark, square, ruled workspace; colour is blended light on thin edges, never flat spectrum bands, status fills or chromatic text. Preserve accessible focus, truthful states and every permission boundary. This supersedes the old warm palette and mint/rose UI.
- Normal maintainer checks: `pnpm install --frozen-lockfile`, `pnpm build`, `pnpm check`, `pnpm test`. Tests may use only temporary synthetic data and must not launch real inference. Run gates only when assigned; workers leave final gates to the integration owner.
- `pnpm package:release` requires real signing/notarization credentials and never publishes. `pnpm package:adhoc` is explicitly unnotarized but uses the production website. Report that limitation; never claim signing/notarization evidence not observed. Public-repository updates use only actual stable releases and validated assets from `jobstash/recruiters-rip-companion`, with SHA-256 verification. Preserve app identity and all local data; source runs never replace their checkout or Electron dependency. Frontend-hosted preview files may still use configured mounts. Never invent download URLs or claim an unpublished release exists.
